# Аудит кромочных случаев диктовки и настроек (0.25.2)

**Дата:** 2026-11-06 · **Тесты:** 641 · **Покрытие DSH 0.2.2-rc.1:** полное

Повод: после релиза 0.25.1 нашлась ложная панель «Диктовка не попала в поле ввода» при длинной диктовке. Проведён системный проход по гонкам и кромочным случаям, а не только по этому багу.

## Что проверялось

| Область | Сценарии | Результат |
|---|---|---|
| Восстановление диктовки | длинное распознавание >8 с, поздняя вставка, дубль по кнопке, несколько диктовок подряд, смена чата, перезагрузка приложения | найдено 4 бага, исправлено |
| Слияние движков | одинаковая/разная разбивка, лишние фразы Whisper, перепутанный порядок, дубли хвоста | найдено 2 бага, исправлено |
| Настройки диктовки | хост не отвечает, ошибка загрузки словарей, Escape во время загрузки, повтор, доктор | найдено 3 бага, исправлено |
| Окно словаря | хост не отвечает, закрытие во время загрузки, повторное открытие | найдено 2 бага, исправлено |
| Host-сервер | история транскриптов для нескольких диктовок, ошибки маршрутов | добавлен endpoint и защита |
| Сеть/порты | кэш рабочего порта, preflight `dsh-app://`, Private Network | исправлено/ускорено |

## Главные находки

1. **Ложная панель recovery.** Длинная диктовка в `auto`/Whisper распознаётся 10–20 с, а наблюдатель вставки ждал 8 с. В `localStorage` оставалась запись с временем ровно готовности транскрипта; в финальном сообщении были две копии — сырая и с токенами ChronoFlow. Причина — не потеря текста, а наш false positive и повторная вставка.
2. **Несколько диктовок подряд.** `scheduleRecoveryCheck` использовал глобальный таймер и `/last-transcription`, поэтому вторая диктовка сбрасывала проверку первой, а recovery мог взять чужой транскрипт. Заменено на очередь с сопоставлением по времени окончания записи и `/transcriptions?after=`.
3. **Вставка в чужой чат.** Recovery вставлял текст в активный композер без проверки сессии. Теперь session id фиксируется при старте записи; при несовпадении текст копируется в буфер, а не вставляется.
4. **Смешивание порядка.** Ручная вставка шла «в текущий курсор» и склеивала диктовки. Теперь recovery вставляет в конец поля с разделителем.
5. **Настройки/словарь зависали при недоступном хосте.** «Загрузка…» и пустой словарь без объяснения. Добавлены ошибки, «Повторить» и предупреждение о недоступном хосте.
6. **Окно могло открыться после Escape/закрытия.** Добавлены generation-guard'ы для словаря и настроек.
7. **Слияние могло дописывать хвост Whisper, дублирующий уже сказанное**, и переставлять фразы при разной разбивке. Исправлено: порядок GigaAM — опорный, хвост добавляется только при фонетической новизне, добавлены защиты от дублей/раздувания.

## Что осталось проверить на живом приложении

- E2E после рестарта: длинная диктовка в двух чатах подряд, смена чата во время распознавания, Recovery → «Вставить».
- Мультиоконность DSH: общий `localStorage` для recovery между окнами.
- Полный корпус из 50 живых транскриптов на реальных движках (сейчас — регрессионные пары и синтетика).

## Инварианты, которые теперь закреплены тестами

- Recovery не показывает панель, если текст уже в поле.
- Панель исчезает при поздней вставке и не дублирует текст.
- Две потерянные диктовки показываются по очереди и обе вставляются.
- Текст из другой сессии не вставляется в текущий чат.
- `/transcriptions?after=` отдаёт только новые записи.
- Escape во время загрузки не оставляет окно открытым.
- При недоступном хосте настройки и словарь показывают ошибку и повтор.
- Слияние не переносит фразы из начала в конец и не дублирует хвост.
