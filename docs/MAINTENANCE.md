# Обслуживание

Короткий чек-лист для сопровождения пакета: что происходит само, что делать после обновления DeepSeek Harness, движка распознавания и жалоб на перевод.

## Что уже автоматизировано

| Что | Когда | Что делает | При сбое |
|---|---|---|---|
| `checks` | push, PR | линтер, импорты, сборка, проверка бандла, документация, согласованность, история, все тесты | смотрите лог упавшего шага, чините локально через `npm test` |
| `dsh-drift` | ежедневно | ставит свежий DSH (`latest`, а на Ubuntu ещё `next` и `alpha`), снимает строки, проверяет дельту и живой индекс маркета | issue «появились строки» или «живой индекс» — см. раздел про новую версию DSH |
| `app-drift` | ежедневно | скачивает сборку приложения из публичного фида, сверяет sha512, проверяет покрытие `app.asar` | issue «новая версия приложения» — та же процедура обновления |
| `engine-smoke` | ежедневно | на Ubuntu и Windows ставит настоящий движок и модель, распознаёт тестовую запись | issue «движок не работает» — проверить релизы gigastt и константы движка |
| `smoke` | push, PR | поднимает `dsh web` с пакетом, проверяет boot-граф и обход интерфейса | падение означает несовместимость с текущей сборкой |
| `pages` | push с изменениями `market/` | публикует индекс и дашборд | проверить `npm run market && npm run dashboard` и права Pages |
| `release` | тег `v*` | публикует пакет в npm через trusted publishing и создаёт GitHub-релиз | если версия уже есть в реестре — публикация пропускается |
| `discussions` | понедельник | проверяет ответы в обсуждениях DSH и открывает или обновляет issue | проверить токен и номера обсуждений |

## Вышла новая версия DSH

1. **Снять дельту.** `npm run refresh` (или `npm run refresh:check`, чтобы только посмотреть). В конце печатается сводка: сколько строк без перевода, сколько изменилось, сколько описаний плагинов не хватает.
2. **Перевести.** Файлы `batches/p3-*.json` (интерфейс) и `batches/plugin-*.json` (описания плагинов) — вручную или черновиком: `npm run translate -- --provider openai --base-url … --model … --api-key-env …`. Результат — черновик: его проверяет вычитка и линтер.
3. **Запомнить раунд.** `npm run mark-translated` — фиксирует, по какому английскому сделан перевод, чтобы дельта не возвращалась.
4. **Проверить.** `npm test` — линтер, согласованность, документация, история и все тесты. При желании: `npm run sweep -- --url "http://127.0.0.1:…/?token=…"` на запущенном сервере (обрезки текста) и `npm run check:app`.
5. **Обновить историю.** `npm run history` — добавляет строку текущей версии в `market/history.json`.
6. **Выпустить.** `npm version patch` (или minor) → `git push --follow-tags`; workflow `release` соберёт, проверит, опубликует с аттестацией и создаст релиз.
7. **Обновить профиль приложения и индекс.** `npx dsh-locale-russian-install --desktop` (для своего профиля) → `npm run market && npm run dashboard` → коммит и push: Pages пересоберёт индекс и дашборд. Проверка: `npm run market:live`.

Если обновление крупное (новая линия версий), расширьте `engines.dsh` в `package.json` — генератор манифеста сохраняет это поле, а `verify` проверяет, что диапазон покрывает линию 0.2.2.

## Вышла новая версия движка распознавания

1. Проверьте релиз [gigastt](https://github.com/ekhodzitsky/gigastt/releases): появилась ли сборка для нужных платформ.
2. Обновите версию в трёх местах: `ENGINE_VERSION` в `tools/templates/host-plugin.js`, `GIGASTT_VERSION` в `install.sh` и ключ кэша `engine-2.22.0-…` в `.github/workflows/ci.yml`.
3. `node tools/engine:smoke` локально (с `--binary` и `--model-dir` уже установленных — без скачивания), затем `npm test` и dispatch CI, чтобы `engine-smoke` прошёл на Ubuntu и Windows.
4. Если изменился размер движка или модели — поправьте цифры в README и FAQ (сейчас 313 МБ на диске).

## Лимит диктовки

Пакет поднимает лимит записи с 2 до 5 минут и объём с 4 до 10 МиБ: это строки `api-speech-to-text` в сгенерированном `cordis.patch.yml`. Патч применяется только если бандл пакета стоит в `dsh.profile.bundles` **после** бандла голосового ввода — установщик ставит и переставляет его сам. Если меняете лимит, меняйте оба значения: 300 с в формате 16 кГц/моно — это ~9,2 МиБ, а штатные 4 МиБ отклонили бы такую запись.

## Личный словарь

- Файл: `~/.dsh/speech-ru/hotwords.txt`; личные фразы живут в помеченной секции `# === личный словарь (dsh-locale-russian) ===`. Формат и лимиты — `lib/hotwords.mjs` (общий для хост-половины и CLI).
- Движок получает словарь **файлом при старте** (`--hotwords-file`), поэтому лимит HTTP-запроса в 64 фразы не действует; файл читается при запуске, изменение подхватывается перезапуском движка (~5 с на первой диктовке).
- Кнопка «+ в словарь» в интерфейсе ходит на локальный endpoint хост-половины: порты `47118–47122` (первый свободный), `POST /hotwords`, CORS открыт для localhost. Если порты заняты, endpoint молча не поднимается — проверять по логу `dictionary endpoint`.
- CLI: `--hotwords-add`, `--hotwords-add-file` (путь «-» — stdin), `--hotwords-list`, `--hotwords-remove`, `--hotwords-clear`, `--hotwords-file`, `--hotwords-export`, `--hotwords-import` (JSON `{version, words, replacements}`, путь «-» — stdin/stdout), `--hotwords-from <папка>`, `--hotwords-limit <n>`.
- Установщик: `pnpm install` повторяется при сбое (`retryDelays` 15/30/45 с) — это гонка с npm-пропагацией сразу после релиза; в тестах повторы отключаются (`retryDelays: []`).
- Сканирование проекта: расширения в `SCAN_EXTENSIONS`, пропускаемые каталоги в `SCAN_SKIP`, стоп-слова в `SCAN_STOPWORDS`, React-хуки (`use*`) не берутся; лимит 150 по умолчанию. Манифест `~/.dsh/speech-ru/projects.json` хранит слова по путям проектов — повторный запуск заменяет прошлый набор, а не дублирует.
- Замены «как услышали → как надо» — `~/.dsh/speech-ru/replacements.json` (модуль `lib/hotwords.mjs`). Пары появляются, когда пользователь выбирает кандидата в поповере: клиент шлёт `POST /learn` с `{heard, chosen}`, хост пишет пару и добавляет выбранное слово в личный словарь.
- Маршруты endpoint: `GET /health`, `GET /dictionary` (слова + замены для клиента), `POST /hotwords` (текст или JSON-строка), `POST /learn` (JSON `{heard, chosen}`), `POST /forget` (JSON-строка или текст — убрать слово из личного словаря).
- Слова в личном словаре сравниваются без учёта регистра: «GitHub» и «github» — дубликат.
- Применение замен: провайдер вызывает `applyReplacements` к тексту расшифровки (границы слов, без учёта регистра), клиент после вставки проверяет поле на выбранные формы и показывает уведомление «Словарь: заменено…» (не чаще раза в 5 секунд).
- Авто-обучение: клиент запоминает текст до диктовки и вставку (общий префикс/суффикс), затем через 900 мс после правок сравнивает слова; пары уходят в `POST /learn`. Пары с похожестью ≥0.8 учатся сразу, ниже — после подтверждения в плашке.
- Движки: `engine` (`gigaam`/`whisper`/`hybrid`), `merge` (`sentences` — по умолчанию, посентенционная оценка; `text`, `auto`, `words`), `debugTranscripts` (пишет `transcripts.json` для разбора). Whisper получает словарь через `--prompt`, GigaAM — через hotwords-файл.
- Качество: `trimSilence` (по умолчанию включено), `silenceThreshold` (0.02 от максимума), `silencePaddingMs` (150) — обрезка тишины перед движком; слова сдвигаются на `audioTrimOffsetSeconds`; `punctuation` (по умолчанию включено) — пробелы, запятые и заглавные без LLM; prompt Whisper собирается динамически (латинские термины и свежие авто-пары приоритетнее, до 60 терминов/600 символов) и кэшируется по сигнатуре словаря.
- Корпус и стенд: `test/corpus/dictation.json` (10 смешанных фраз), `npm run harness:dictation -- --corpus test/corpus/dictation.json --json report.json` — WER, точность терминов и задержка по каждой стратегии; по умолчанию sentences выигрывает (8.6% против 11.3% у Whisper и 27.7% у GigaAM; термины 97%)
### Контракты для внешних клиентов (Chronoflow)

Эти вещи проверены на живом Chronoflow и ломать их нельзя:

- `GET /last-transcription` слушает порты **47118–47122** и отдаёт CORS `*`.
- **Безопасность**: сервер отклоняет cross-site запросы (`Sec-Fetch-Site: cross-site` с непустым Origin) и чужие `Host` — чтобы сайт в браузере не мог прочитать последнюю диктовку или писать в словарь. Same-site (веб-ГУИ на другом порту) и Electron (`Origin: null`) разрешены.
- `at` — epoch ms момента окончания распознавания: клиенты отсеивают по нему устаревшие ответы.
- Поля `raw`, `text`, `applied`, `mode` не меняются; новые поля добавляются только аддитивно.
- `words[] {word, start, end, confidence}` — тайминги GigaAM в секундах от начала аудио; `wordsSource: "gigaam"`; `gigaamText` — текст GigaAM до замен (в hybrid итоговый текст может отличаться); `audioDurationSeconds`.
- `[data-voice-activity]` принимает значения `recording` / `transcribing` / `feedback` / `idle`.
- Keep-alive: диктовка не отменяется по blur/visibilitychange.
- Патчи `window.MediaRecorder` (Proxy) и `EventTarget` идемпотентны — Chronoflow патчит `MediaRecorder.prototype`, патчи должны сосуществовать и восстанавливаться.

- Стенд диктовки: `npm run harness:dictation -- --text "..."` — TTS (`say`/`afconvert`), реальные движки, WER по словам; требует macOS и установленные GigaAM/Whisper, в npm test не входит, `whisperBinaryPath`, `whisperModelPath`, `whisperLanguage`. Гибрид запускает оба параллельно и сливает пословно: LCS по нормализованным словам, латинские термины из Whisper, остальное из GigaAM; страховка — сравнение по `termHits` (если слияние потеряло термины, берётся лучший исходный текст).
- Фоновый перезапуск движка: вотчер `hotwordsWatchMs` (по умолчанию 2000 мс) сравнивает mtime словаря и перезапускает движок, когда диктовка не идёт. Шум (ссылки, числа, код, переписанные фразы) отфильтрован. Работает только в окне 60 секунд после вставки.

## Изменился код отмены диктовки

Пакет сохраняет диктовку в фоне, подавляя два штатных обработчика (`blur` и `visibilitychange`), которые отменяют запись. Обработчики узнаются по исходному коду, поэтому их изменение в DSH ломает патч молча. От этого защищает `npm run check:voice-hook`: локально он проверяет `.app-packages`, а в job `app-drift` — распакованные пакеты свежего приложения. Если проверка упала — обновите `installVoiceKeepAlive` в `tools/templates/client-bundle.js` под новый код и прогоните `npm test`.

## Пользователь сообщил об ошибке перевода

1. Правьте `dictionary/overrides.json` (интерфейс) или `dictionary/plugin-meta-overrides.json` (описания плагинов) — это слои поверх батчей, они не теряются при обновлении строк.
2. Сверьтесь с `GLOSSARY.md` и `STYLE.md`; `npm run check-consistency` покажет, не разошёлся ли одинаковый английский текст.
3. `npm test`, затем патч-релиз (`npm version patch && git push --follow-tags`) и обновление профиля.

## Что делать, если упал CI

- **checks** — воспроизведите локально: `npm test` (включает линтер, сборку, документацию и все тесты).
- **dsh-drift / app-drift** — значит, изменились строки или сборка: пройдите раздел «Вышла новая версия DSH».
- **engine-smoke** — проверьте, доступен ли релиз движка для платформы и не изменился ли формат архива; локально: `node tools/engine:smoke`.
- **smoke** — пакет не совместим с текущей сборкой DSH: смотрите лог boot-графа, проверьте, что клиентский бандл активируется (verify).
- **release** — версия уже опубликована или тег не совпадает с `package.json`; публикация идёт через trusted publishing, секреты не нужны.

- **Еженедельно:** просмотреть открытые issue (детектор дрейфа открывает их сам), ответить в Discussions.
- **Раз в месяц:** сверить теги DSH (`npm view @deepseek-ai/dsh dist-tags`), версию движка, загрузки и звёзды; проверить, что живой индекс и дашборд отдают актуальную версию.
- **После крупных обновлений DSH:** перечитать `docs/FAQ.md` и README — не изменились ли названия разделов интерфейса (ярлыки мы сверяем с реальным словарём).

## Посты в соцсетях (по запросу)

Публикация в Threads — **необязательный шаг**, и делается только по явной просьбе. Порядок: пользователь говорит, что пора, а мы **уточняем, после какого обновления** делать пост (версия и что в нём главное), готовим текст и карточку, публикуем и присылаем ссылку.

- Рецепт: `~/Developer/dsh-mobile-client/docs/THREADS-AUTOMATION.md` (Chrome + AppleScript JS + cliclick, вход в аккаунт вручную).
- Аккаунт: `@golova_2uxa`; лимит поста — 500 символов, держим 300–480.
- Карточка: 1200×630, JPEG ~800 px; текст вставлять через буфер обмена и реальный клик, кнопку публикации нажимать через `cliclick`.
- После публикации: проверить текст и картинку глазами, взять ссылку из профиля.
- Посты: 0.9.0 — https://www.threads.com/@golova_2uxa/post/DfQaC9KjXi4

## Известные ограничения

- Пакет опирается на два приватных метода локали (`translate`, `resolveText`); они защищены проверкой типа — при исчезновении пакет работает, но склонения и описания плагинов деградируют. Предложения в upstream: [хук склонений](https://github.com/deepseek-ai/deepseek-harness/discussions/10147), [локализация оболочки](https://github.com/deepseek-ai/deepseek-harness/discussions/10148), [локализуемые описания навыков](https://github.com/deepseek-ai/deepseek-harness/discussions/11533).
- Оболочка Electron и описания навыков в меню `/` остаются английскими — это вне возможностей плагина.
- Движок распознавания есть для macOS arm64, Linux x64/arm64 и Windows x64; macOS Intel не поддерживается.
