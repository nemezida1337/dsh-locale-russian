# Обслуживание

Короткий чек-лист для сопровождения пакета: что происходит само, что делать после обновления DeepSeek Harness, движка распознавания и жалоб на перевод.

## Что уже автоматизировано

| Что | Когда | Что делает | При сбое |
|---|---|---|---|
| `checks` | push, PR | линтер, импорты, сборка, проверка бандла, документация, согласованность, история, все тесты | смотрите лог упавшего шага, чините локально через `npm test` |
| `dsh-drift` | ежедневно | ставит свежий DSH (`latest`, а на Ubuntu ещё `next` и `alpha`), снимает строки, проверяет дельту и живой индекс маркета | issue «появились строки» или «живой индекс» — см. раздел про новую версию DSH |
| `app-drift` | ежедневно | скачивает сборку приложения из публичного фида, сверяет sha512, проверяет покрытие `app.asar` | issue «новая версия приложения» — та же процедура обновления |
| `engine-smoke` | ежедневно | на Ubuntu и Windows ставит настоящий движок и модель, распознаёт тестовую запись | issue «движок не работает» — проверить релизы gigastt и константы движка |
| `smoke` | push, PR | поднимает `dsh web` с пакетом, проверяет boot-граф и обход интерфейса | падение означает несовместимость с текущей сборкой |
| `pages` | push с изменениями `market/` | публикует индекс и дашборд | проверить `npm run market && npm run dashboard` и права Pages |
| `release` | тег `v*` | публикует пакет в npm через trusted publishing и создаёт GitHub-релиз | если версия уже есть в реестре — публикация пропускается |
| `discussions` | понедельник | проверяет ответы в обсуждениях DSH и открывает или обновляет issue | проверить токен и номера обсуждений |

## Вышла новая версия DSH

1. **Снять дельту.** `npm run refresh` (или `npm run refresh:check`, чтобы только посмотреть). В конце печатается сводка: сколько строк без перевода, сколько изменилось, сколько описаний плагинов не хватает.
2. **Перевести.** Файлы `batches/p3-*.json` (интерфейс) и `batches/plugin-*.json` (описания плагинов) — вручную или черновиком: `npm run translate -- --provider openai --base-url … --model … --api-key-env …`. Результат — черновик: его проверяет вычитка и линтер.
3. **Запомнить раунд.** `npm run mark-translated` — фиксирует, по какому английскому сделан перевод, чтобы дельта не возвращалась.
4. **Проверить.** `npm test` — линтер, согласованность, документация, история и все тесты. При желании: `npm run sweep -- --url "http://127.0.0.1:…/?token=…"` на запущенном сервере (обрезки текста) и `npm run check:app`.
5. **Обновить историю.** `npm run history` — добавляет строку текущей версии в `market/history.json`.
6. **Выпустить.** `npm version patch` (или minor) → `git push --follow-tags`; workflow `release` соберёт, проверит, опубликует с аттестацией и создаст релиз.
7. **Обновить профиль приложения и индекс.** `npx dsh-locale-russian-install --desktop` (для своего профиля) → `npm run market && npm run dashboard` → коммит и push: Pages пересоберёт индекс и дашборд. Проверка: `npm run market:live`.

Если обновление крупное (новая линия версий), расширьте `engines.dsh` в `package.json` — генератор манифеста сохраняет это поле, а `verify` проверяет, что диапазон покрывает линию 0.2.2.

## Вышла новая версия движка распознавания

1. Проверьте релиз [gigastt](https://github.com/ekhodzitsky/gigastt/releases): появилась ли сборка для нужных платформ.
2. Обновите версию в трёх местах: `ENGINE_VERSION` в `tools/templates/host-plugin.js`, `GIGASTT_VERSION` в `install.sh` и ключ кэша `engine-2.22.0-…` в `.github/workflows/ci.yml`.
3. `node tools/engine:smoke` локально (с `--binary` и `--model-dir` уже установленных — без скачивания), затем `npm test` и dispatch CI, чтобы `engine-smoke` прошёл на Ubuntu и Windows.
4. Если изменился размер движка или модели — поправьте цифры в README и FAQ (сейчас 313 МБ на диске).

## Пользователь сообщил об ошибке перевода

1. Правьте `dictionary/overrides.json` (интерфейс) или `dictionary/plugin-meta-overrides.json` (описания плагинов) — это слои поверх батчей, они не теряются при обновлении строк.
2. Сверьтесь с `GLOSSARY.md` и `STYLE.md`; `npm run check-consistency` покажет, не разошёлся ли одинаковый английский текст.
3. `npm test`, затем патч-релиз (`npm version patch && git push --follow-tags`) и обновление профиля.

## Что делать, если упал CI

- **checks** — воспроизведите локально: `npm test` (включает линтер, сборку, документацию и все тесты).
- **dsh-drift / app-drift** — значит, изменились строки или сборка: пройдите раздел «Вышла новая версия DSH».
- **engine-smoke** — проверьте, доступен ли релиз движка для платформы и не изменился ли формат архива; локально: `node tools/engine:smoke`.
- **smoke** — пакет не совместим с текущей сборкой DSH: смотрите лог boot-графа, проверьте, что клиентский бандл активируется (verify).
- **release** — версия уже опубликована или тег не совпадает с `package.json`; публикация идёт через trusted publishing, секреты не нужны.

## Периодически

- **Еженедельно:** просмотреть открытые issue (детектор дрейфа открывает их сам), ответить в Discussions.
- **Раз в месяц:** сверить теги DSH (`npm view @deepseek-ai/dsh dist-tags`), версию движка, загрузки и звёзды; проверить, что живой индекс и дашборд отдают актуальную версию.
- **После крупных обновлений DSH:** перечитать `docs/FAQ.md` и README — не изменились ли названия разделов интерфейса (ярлыки мы сверяем с реальным словарём).

## Известные ограничения

- Пакет опирается на два приватных метода локали (`translate`, `resolveText`); они защищены проверкой типа — при исчезновении пакет работает, но склонения и описания плагинов деградируют. Предложения в upstream: [хук склонений](https://github.com/deepseek-ai/deepseek-harness/discussions/10147), [локализация оболочки](https://github.com/deepseek-ai/deepseek-harness/discussions/10148), [локализуемые описания навыков](https://github.com/deepseek-ai/deepseek-harness/discussions/11533).
- Оболочка Electron и описания навыков в меню `/` остаются английскими — это вне возможностей плагина.
- Движок распознавания есть для macOS arm64, Linux x64/arm64 и Windows x64; macOS Intel не поддерживается.
